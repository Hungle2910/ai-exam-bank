# Host preparation templates

These scripts are prepared for a future authorized deployment. They have not been run on EC2. Do not execute `fetch-runtime-secret.sh` during the current local-only phase: it calls AWS. No script launches EC2, changes IAM or formats a disk.

1. Pin Ubuntu 22.04 x86_64 AMI and exact versions/checksums for .NET 10 ASP.NET runtime, Caddy, SQL Server 2022 CU, AWS CLI and SSM Agent. Build a reviewed package/dependency manifest; no download-to-shell installers are used here.
2. On each authorized host, inspect its preinstalled SSM Agent and run `check-host.sh`. Use `install-reviewed-package.sh` only with a verified local `.deb` and independently obtained SHA256; provision dependencies from the reviewed manifest. The installer does not automatically resolve dependencies or enable a complete service stack.
3. Entry: install the reviewed Caddy package, preserve its certificate storage, install the Web build and replace example DNS/app-address values in the Caddy template. Bind the real domain and validate TLS-ALPN on 443. Forwarded headers and a same-origin login flow must be integrated with the shared authentication implementation before using it behind the proxy.
4. App: create a non-login `aieb` service user, publish the API under `/opt/aieb/api/<release>` and atomically point `current` at that release. Install the reviewed ASP.NET runtime, then review/install the systemd template. Keep local preview disabled. This release still denies all protected requests until shared authentication is integrated; do not treat it as deployed admin functionality. A Worker service is added only when a real Worker host/handler exists.
5. DB: identify the retained EBS device/UUID, validate backups, and mount it at `/var/opt/mssql` before installing/configuring SQL. Disk formatting is deliberately not automated. Install SQL Server 2022 Developer from the reviewed package manifest. Install a certificate matching the internal DNS name, grant the `mssql` user certificate/key read access, and trust its CA on the app host.
6. With approved runtime permissions, use the secret-fetch script on the corresponding host. It writes a root-only file under `/run/aieb`; it does not install persistent credentials. Run `configure-sql.sh` only for a new, empty SQL data volume. Create separate restricted app/migration logins and verify encrypted connections; the app must not use `sa`.
7. Integrate the app connection-string file with the shared persistence/configuration adapter when that adapter exists. It is not consumed by the current UNKNOWN health stub. Do not copy it into Terraform, service unit files, logs or source.

The setup selects SQL Developer and a 4096 MiB SQL process memory limit; the later SQL configuration should also set/verify the intended `max server memory` value using an authorized SQL connection. Daily backup scheduling, application log shipping and Session Manager logging preferences still require runtime configuration and live checks. Their presence in the design does not mean these templates have enabled them.
